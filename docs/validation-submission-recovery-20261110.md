## 自动核对与移除手机人工清除入口（同日追加）

- 移除手机端“清除等待记录”对话框、菜单入口及 `finishReconciliation` 方法。未知提交不能由 UI 清空去重记录或解除提交锁。底部只显示一次自动消失的恢复提示。
- 轮询由 `SubmissionCoordinator` 的节点协程作用域持有，恢复保存的提交 ID 后自动启动；首次等待 3 秒，此后每 10 秒核对，不依赖当前会话页面，也不会重新 POST 原操作。接受或明确失败、并成功保存本地结果后停止轮询。
- 收据 GET / reconcile 在 unknown 时只读原生历史，以精确 `clientId` 找回 turn 回执；覆盖发送、继续、问题回答，以及已保存原队列 itemId 的引导。每轮读取最近页和最多 5 个历史页，保留翻页进度；游标失效重新定位，暂时超时保留进度。不会按文字相似、等待时长或历史缺失判定未执行。
- 新建及分叉会话新增 preparing / dispatching / received 落盘；收到原生 threadId 后，先保存回执，再更新派生元数据。节点重启后，已收回执自动转 accepted，确定未发送的准备阶段转 failed。
- 队列入队、编辑、移除、排序、恢复记录等本地数据库操作与接受回执在同一事务中提交。提交前崩溃可确定失败，提交后通知失败仍返回已接受。历史入队 unknown 可通过相同 ID、所属连接和会话的持久队列记录找回回执。

### 尚不能保证自动终结的边界

若原生请求已发出，但进程在回执落盘前退出，且原生侧没有保存可关联的 `clientId` / threadId 或可查询回执，Relay 无法证明是否执行。新建会话的 `thread/start` 当前未使用可持久查询的幂等提交 ID，其他未覆盖的原生写入也没有通用的结果查询协议。此时仍保持 unknown 并保留去重，不能宣称“任何故障都必定解锁”。历史旧记录也不能仅凭年龄自动判失败。

本次关闭了可证明的恢复缺口，但不靠超时清锁或自动重发来制造收敛。要同时保证这一极端窗口中“不重复执行”和“必定结束等待”，仍需要原生端提供持久幂等键及权威状态查询，或可证明未执行的取消/隔离协议。

## 状态与并发审查补充

本轮按首次提交、超时、重启、核对、结果落盘、草稿清理及并发进入逐段审查，发现并修复以下问题：

| 问题 | 修复与验证 |
| --- | --- |
| SQLite 在 COMMIT 阶段抛错不进入原有回滚分支，连接可能继续看见未提交的“accepted” | 将 COMMIT / RELEASE 纳入异常回滚范围；模拟外层队列事务提交失败，确认队列写入和接受回执一起回滚，后续事务可正常执行 |
| 手机接受缺少回执身份、错误提交 ID 或错误会话的结果 | 在协调器和独立收据读取路径验证身份；异常结果保留等待，不能触发成功回调或清理草稿 |
| 损坏的持久等待记录被解析为 null，形成假解锁 | 保留损坏原文并拒绝建立可提交协调器，不再静默忽略；这类本地损坏无法凭空恢复已丢失的 ID |
| 手机自动轮询与其他触发同时进入，存在检查后更新的竞争窗口 | 用 StateFlow CAS 原子占用提交/核对状态；40 个并发核对调用只产生一次请求 |
| 服务端慢历史查询占用全局恢复锁 | 改为只合并相同提交 ID，其他提交可独立核对；阻塞一个查询时另一条仍能完成 |
| 孤立草稿恢复记录只核对一次，暂时读写失败后停止 | 在节点作用域持续重试直到无记录；每轮动态跳过当前协调器拥有的 ID，避免重复处理回调和全局锁 |
| 新建缺少 threadId 或发送回执指向其他会话时，存储层仍可能退休恢复记录/清理草稿 | 在原子元数据更新前验证创建身份、发送草稿所属会话；孤立恢复先处理持久结果，再更新显示覆盖层 |
| 错误的历史显示 threadId 可污染后续回执校验 | 以冻结请求路径推导期望会话，不以可更新的展示字段为准；正确回执仍能终结恢复 |

## 第二轮独立审查补充

- 发现准备阶段的所有权窗口：附件准备/上传或 `prepared` 建立覆盖记录时，协调器已 busy 但 pending ID 尚为空，孤立记录恢复可能提前对仍未发送的 ID 执行 missing fence。改为 CAS 占用提交时同时公开 ID，准备异常统一走结果记录和释放流程；后台恢复与协调器都不会查询仍在准备的请求。
- 发现成功后异步草稿清理失败只有报错，没有保证重试任务仍在运行。该分支现在主动启动持久记录恢复；仍由原 ID 的记录完成清理，不重复发送。
- 新增准备中禁止提前核对、准备异常无网络提交且正确退休记录两项回归。最终 Android 应用与 UI 测试代码编译通过，提交、收据、待发送恢复及状态一致性 49 项单元测试通过；服务端未改动，复用前轮服务端结果。
- 本轮另行检查事务提交后通知失败、重复请求返回已有结果、历史查询并发合并、回执落盘失败及新会话创建阶段；未发现需要追加修改的其他确定问题。原生身份/证据全失、旧记录缺少发送阶段的边界仍然存在，不能据此宣称所有中断都能自动解锁。
