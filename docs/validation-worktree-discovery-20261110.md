# 工作区探测缓存优化验证

## 问题与变更

0.2.103 运行日志仍出现 GET 会话请求 4341.76 ms，其中工作区关联路径上的锁等待为 2582.85 ms。代码中 ExternalWorktrees 只有一个 15 秒缓存槽，后台全局查询、前台项目查询及单会话查询使用不同键，会互相覆盖；原生探测期间持有同一把锁。

改为最多 8 项的 LRU 缓存，每项仍保留 15 秒有效期，键仍包含运行时 generation 和完整查询。按查询键合并并发探测，缓存命中不等待其他键的探测。锁引用单独管理，不因缓存淘汰导致重复扫描。保留原生宿主执行、工作区归属歧义判断、取消和 generation 校验；传给观察记录的关联对象复制后使用。

## 验证

- `test_external_worktree_performance` 与 `test_native_files_worktrees`：15 项通过；新增同键并发测试后单独重跑前者，9 项通过（合计覆盖 16 项不同测试）。
- 新增覆盖交替查询缓存复用、其他慢探测不阻塞缓存命中、同键请求合并、等待取消、缓存过期、generation 隔离、容量上限。已有真实 Git 测试覆盖共同根歧义、宿主边界和下一次扫描读取新 commit。
- 受控对比：加载 HEAD 原实现及修改实现，模拟同一个原生探测函数（含 0.1 秒等待），两种查询交替执行 10 次。原实现探测 10 次，总耗时 2951.82 ms；修改后探测 2 次，总耗时 590.16 ms。宿主调度影响绝对耗时，此结果仅验证缓存减少重复探测，不代表线上延迟。
- 审查时补强同键并发测试：第二个请求确实进入锁等待后才释放首次探测，避免仅验证顺序缓存命中；9 项针对性测试再次通过。
- `git diff --check` 通过。

## 范围与限制

本次未部署，未进行 Android 真机或模拟器验证。不同键的冷查询仍需要原生探测，且可并发执行；缓存 TTL 内 Git 状态最多保持原有 15 秒陈旧窗口。后续应关注冷查询耗时及原生宿主并发负载，不能将本次结果表述为线上已经生效。
