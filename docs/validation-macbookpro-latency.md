# MacBook Pro 长会话延迟验证（2026-11-09）

目标为设备清单中的 MacBook Pro（通过 SSH 别名 macbookpro），读取实际 LaunchAgent 的 PYTHONPATH，对应部署 `367473a54257b1dac8beb7163dad9bea9bdae7c2`。没有替换部署、重启原生运行时、发送任务或修复历史。此前 Mac mini 的目录优化测量不能代表此节点的手机端体验。

## 实测

从只读状态库选择最大未归档历史，以及最近 20 个会话中最大的历史：共 1,146 个未归档会话，两个样本文件为 117,719,504 和 77,079,834 字节。独立连接测 `get_session(limit=5)` 加客户端投影：首次分别 0.516 / 0.276 秒，同连接第二次 0.132 / 0.127 秒；JSON 响应约 21,726 / 48,541 字节。原生历史校验均 ready/verified。

探针禁用历史重建、拒绝 resume 等修改 RPC，强制走只读查看分支，因此不代表生产路由选取、真实 writer 管理、手机传输或渲染的端到端耗时。此前探针因拒绝 resume 而中断的结果不计为成功测量。输出只保留大小、耗时、调用种类，不保存标题或消息内容。

按 request_id 关联最近一小时节点与 VPS 日志：521 条成功 threads 类请求，网关总时长减节点总时长的中位数约 141 ms，P95 约 10,984 ms，最大约 23,852 ms。最慢额外耗时样本在北京时间 20:49:37：节点 111.72 ms，网关 23,963.73 ms。该差值包含数据连接、上下行传输及向客户端写入，不能直接称为纯网络延迟，也不能凭现有 route=threads 断言是详情而非列表请求。

节点项目请求 6 次成功，耗时约 12–14 秒；另有 6 次 504。会话类成功 529 次，中位数 118 ms，P95 887 ms，最大 15.245 秒；12 次 504 的原日志不能区分取消与超时。排除长驻 SSE events 的正常长时长。

MacBook Pro 经 VPS 回到本机的 `/health` 三次测量为 0.278 / 0.306 / 0.278 秒，均 200，响应 103 字节。它只能证明小响应当时正常，不排除大响应或间歇拥塞，也不覆盖手机网络。

原始脱敏统计与探针位于 `workspace/artifacts/macbookpro-analysis/`。

## 本地改动

Android 连续 command 活动分组原来每追加一个条目就遍历已有组，长工具回合出现 O(N²) 工作且位于 UI 投影路径。改为根据组首条目判断，保持分组边界与顺序，将该部分降为 O(N)。新增 8,002 条混合工具消息回归，17 项相关单测与必要 Debug Kotlin 编译通过。未声称此处已被真机性能分析确认为主要瓶颈。

网关增加等待数据连接、响应头、body 转发阶段耗时与响应字节数，定位已证实的额外等待；不记录 URL、正文或凭据，不改变转发语义。

未构建 APK、未运行 lint、未做真机 UI 性能分析；本轮未提交、推送或发布。仍需指定用户实际慢会话，结合分阶段线上日志确认主要瓶颈，不能把本次局部优化视为端到端问题已解决。

网关分阶段日志 7 项针对测试通过（含慢读、取消、脱敏与请求不重放），`git diff --check` 通过。`downstream_write_ms` 是 body 阶段的子集，仅反映本地异步写入等待；写入字节数不等于手机确认接收字节数。

## 同会话深入复现与修复

无需用户另选样本，继续使用上述两个会话。通过正式 PairingStore 创建临时诊断连接，在运行中的 HTTP 服务比较本机直连与 VPS 中转，结束后撤销成功。第一样本 `limit=5` 两条路径均 200，约 0.452 / 0.268 秒；`limit=30` 两条路径均 503/native_history_unavailable。第二样本 `limit=30` 均 200，中转约 0.209 秒，压缩正文 159,573 字节。本次客户端位于 MacBook Pro，不覆盖手机接入网络。

独立原生 WebSocket 证据：第一样本 `limit=30` 触发客户端 close_sent=1009（消息过大），当时上限为 32 MiB。缩小为 10 轮后前两页正常，但第三页仍断开；继续缩到 1 轮，发现一轮响应为 58,110,449 字节，其中二十多项 imageGeneration 包含大块内嵌图片。单纯减少轮数无法解决该单轮。

本地修复：原生分页最多 10 轮，保留原生游标，不拼接填满；历史包含性搜索保持原有最多 10,000 轮范围，每页检查取消预算。单条原生消息上限提升至有限的 128 MiB，接收队列降到 4 帧；超过上限给出明确大小错误，不重放请求。移动投影在媒体登记成功后将已完成图片的内嵌数据换为稳定媒体引用，原生历史不改写。

将新源码复制到 MacBook Pro `/tmp/rivo-latency-fixed-20261109`，独立只读连接运行，未替换 LaunchAgent 或生产部署。第一样本连续三页返回 10/10/7 轮，页间无重复，末页无后续游标，耗时 0.407 / 0.098 / 3.362 秒。问题页 canonical JSON 58,641,951 字节，手机投影 313,838 字节，gzip 93,663 字节；原先 1009 断连消失。第二样本三页均 10 轮、无重复，0.261 / 0.104 / 0.098 秒。

该隔离测量包含原生读取、校验和移动投影，不含真实媒体落盘处理、VPS及手机收取/渲染。它验证了具体单轮过大问题的修复，尚不能宣称既往所有中转长尾都已解决。输出记录于 `http-probe.log`、`frame-probe.log`、`frame-single.log`、`frame-large.log`、`probe-fixed.log`。

传输回归包含真实 33 MiB 本地 WebSocket 夹具和有限大小拒绝，连同原 transport 与日志测试共 6 项通过；历史读取优化 18 项通过。既有 activity 测试按每次读取实时检查一次 writer 锁修正了过时的总次数断言，并验证缓存命中与锁状态改变后仍实时检查。

图片部分最终验证：Python 10 项不同用例通过，包含真实临时 PNG 登记、素材处理完成后按稳定 identity 读取原始字节一致，以及 HTTP/SSE 登记先于投影、登记失败保留内嵌数据；Android 8 项通过并完成必要 Kotlin 编译，覆盖 pending→ready、媒体请求与缓存。分页/兼容 10 项通过，另复核 NativeSemantics。临时远端源码目录已删除，无遗留测试服务；诊断配对已撤销。尚未发布或完成手机端验证。

## 桌面新会话发现与任务状态维护

本轮重点改为两个验收目标：桌面新建能尽快出现在 App 列表；运行、等待、排队和完成状态及时核对，不被轻量摘要或晚到结果覆盖。

- 可见列表复用同一节点 SSE，生命周期、新建、队列和审批事件触发合并刷新，排除 token/delta 洪泛。无事件时每约 3 秒独立查询轻量摘要，不等待完整扫描。
- 完整状态核对在上次读取结束后，运行/未知约 3 秒、空闲约 5 秒再读，不叠加请求。实际延迟还包含请求与调度耗时，不承诺严格三秒；独立运行模式下桌面事件并非必达，因此保留轮询兜底。
- 摘要仅合并名称等元数据，保留已确认的运行、等待、队列、恢复状态。新详情使用逐会话观察版本保护；晚到全量只保护真正被更新的会话，不冻结其他会话状态，也不取消整份补全。新摘要时间更晚时保留其名称/预览/时间，落盘保存合并后的状态。
- 服务端摘要发现新 ID、删除或原生 status 变化时，失效旧完整目录缓存；与扫描并发时旧扫描结果不能重新进入缓存。首次状态库观察不会把 rollout-only 会话当作删除。这避免没有 SSE 时新会话先出现、再被旧缓存移除。
- 摘要发现置顶只追加订阅；只有完整列表允许删除既有订阅。
- historyUnchanged 只复用消息，状态、goal、审批、队列、恢复与权限均用新响应。明确结束事件触发事件之后的新鲜读取；已知运行轮次离开最近两轮或重连时最多补查三页同版本历史，找到真实结束证据才通知。超出有限补查范围或服务端持续失败时保持未决，不宣称所有历史完成通知必达。
