# 目标模式会话

2026-11-07：Android 会话页支持原生持续目标。进入已创建的会话后可设置目标；已有目标显示正文、状态、Token 用量/预算和累计耗时，支持编辑并启用、暂停、继续及清除。目标独立于 Plan 模式；暂停/继续使用原生目标接口，停止按钮仍调用当前轮次的中断接口。清除目标不删除会话历史。

2026-11-07 更新：设置入口改为输入栏“普通模式”右侧的靶心图标，启用时高亮；已有目标仍可在目标面板暂停、继续和清除。原生目标为 `active` 时，会话详情及列表保持运行中，包括自动续跑的轮次间隙；新任务进入队列。等待用户回应优先显示等待状态。停止按钮仍只在存在真实活动轮次时显示，不把目标伪装成活动轮次。

## 2026-11-08 新建流程、交互与恢复

- 新建页通过鉴权只读接口 `GET /v1/goals/capabilities` 预检目标能力。不支持时不提供新增入口；读取失败可重试。已有目标草稿保留，可移除目标后普通发送。带目标的首条消息同时传 `requireGoalSupport=true`，服务端在发送前再次检查，不支持时不启动首轮。
- 预检读取固定不存在的 thread ID，不创建或 resume 线程。只有明确的方法不支持返回 false；当前原生协议明确的 thread-not-found 响应证明 get 已被识别，其余错误原样报告，不把连接/鉴权故障伪装为不支持。
- 新建会话可保存目标和可选预算；仅填写目标也可发送，目标正文作为首条输入。目标独立于普通/Plan 模式。
- 目标草稿属于有效内容：返回会话列表、应用重启、草稿搜索与恢复均保留目标，不按空草稿删除。
- 提交顺序为：创建会话 → 首轮发送并收到 accepted 回执 → 设置 active 目标。原生实测证明 active 会自行启动轮次，因此不能先启用再发送。先发送也让首轮模型、模式与附件先落实到会话。三次提交不是事务，首轮被接收不代表目标已启用。
- 首轮发送前保存 `sendWithGoal` 检查点，包含冻结的目标操作；accepted 后保存 thread/turn 回执与待设置目标，不立即完成整个新建流程。未知结果只核对原 submissionId，不自动重发。应用重启后“完成目标设置”只提交冻结目标，不重发消息；目标 accepted 后才原子保存完成标志与会话 ID。
- 目标待设置期间禁止继续修改该草稿，列表标注“任务已发送 · 目标待设置”。可直接查看已发送任务，在真实会话中停止或回应；删除待办草稿只放弃后续目标设置，不停止已经发送的任务。
- 目标编辑发送失败后，在当前页面重新打开编辑器保留输入；显式取消则放弃修改。尚未保存的编辑框内容不等同于持久草稿。
- 预算为可选正 64 位整数。新目标留空不传预算，已有目标留空不修改预算；不提供“留空清除既有预算”的语义。受预算/额度限制时，“尝试继续”不保证成功，最终判断由原生运行时负责。
- 暂停目标、停止当前轮次、清除目标是不同操作。它们不会删除队列；目标暂停或结束后，其他已排队任务仍可能执行。停止弹窗与目标面板明确提示此边界。
- 手机上的目标写操作来自用户明确操作，原生 set/clear 一律传 `origin=user`；协议指出省略 origin 不构成用户授权。Relay 不添加自动续跑循环。

### 恢复与通知补充检查

- 新建阶段推进、完成标志、会话 ID 和旧提交检查点的删除合并为一次原子 metadata 写入。回执处理在目录共享锁内读取持久状态，删除草稿后的迟到回执只能退役旧记录，不能重建目标待办。
- 启动及重新连接恢复同时扫描发送草稿、独立的新建/目标检查点和未确认消息展示记录；即使发送草稿已经标记 accepted，仍先核对尚未完成的新建记录。恢复查询 submission；节点不存在该 ID 时，通过原子核对接口阻止迟到请求后再解除等待，不自动重发消息或目标写操作。
- “结束手机等待”不代表原操作取消。每个新建草稿仍检查自己的未决提交；未确认前阻止发送和编辑，并提供“核对新建结果”。删除该草稿仍不取消原生任务。
- 目标结束和最后一轮结束可能分开到达。通知跟踪目标所属的活动轮次，避免后到的轮次完成再次通知；真实失败仍报告，之后独立任务的完成通知不受影响。
- 新增回归覆盖跨 store 实例的迟到回执、仅有目标检查点的重启恢复、重复完成回执，以及目标完成/受阻/额度限制后迟到的轮次完成。未用这些单元测试替代设备断网与进程强杀验收。

### 本轮原生验证范围

在本机独立 writer 和隔离目录内进行短时协议验证，未操作既有会话，也未重启原生 daemon：

- 旧顺序测试线程 `01a1b75e-2972-77b1-a034-9a6bf3ca3a5c`：未发送消息，设置 active 后出现 `turn/started`，确认抢跑风险。
- 新顺序测试线程 `01a1b760-d6b0-70b0-b840-28003c86087f`：首轮回执返回后设置目标，观察到首轮 started 在目标 updated 之前；两秒观察窗口内没有额外抢跑轮次。结束时清除目标、中断仍活动的测试轮次并关闭自己的 writer。
- 原生 ephemeral 线程不支持目标；验证改用隔离的普通线程。不将 ephemeral 失败算作目标流程通过。

本轮另运行目标/新建恢复相关 Android 单元测试与编译，以及服务端目标权限、能力预检、提交参数和去重回归。尚未做真机/模拟器 UI 验收、长时间自动续跑或额度耗尽的端到端验证，未发布。

## 协议与同步

- 协议按本机 `codex-cli 0.159.2` 的 `app-server generate-json-schema --experimental` 输出核对：`thread/goal/get`、`thread/goal/set`、`thread/goal/clear`。
- 会话快照增加 `goal` 和 `goalSupported`。每次快照读取原生目标，不从聊天文字推测目标，也不把目标持久化为 Relay 自己的执行状态。Android 原有快照缓存保留展示数据，离线时禁用操作。
- `POST /v1/threads/{id}/goal` 使用现有鉴权和 submissionId 去重。operation 为 set/pause/resume/clear，原生写入标记 `origin=user`；set 接收 objective 和可选正整数 tokenBudget，省略预算不修改已有预算。暂停/恢复只设置 paused/active，不发送额外提示词、不建立手机端续跑循环。
- 未实现目标 RPC 的节点（JSON-RPC -32601）返回 `goalSupported=false`，保留普通聊天。其他原生错误仍报告，避免把读取故障显示为“没有目标”。旧 Relay 未返回字段时 Android 不显示控制入口。
- 原生 goal/updated、goal/cleared 事件沿现有 SSE 触发权威快照刷新。带 turnId 的目标事件不创建虚假的运行中轮次。
- 目标会话中间轮次完成不触发任务完成通知；目标完成、受阻或达到预算/额度限制才通知。原生提问与真实轮次失败仍保留通知。
- 使用外部 writer 的只读会话可以查看目标，不能从手机绕过持有者修改。继续或启用目标是否立即执行以及预算限制由原生运行时决定。
