# Rivo Relay 产品说明

## 产品定位

Rivo Relay 是一个自托管的 Codex 移动工作台，产品目标是成为 Codex Desktop 在手机上的完整延续。用户从手机继续桌面的 Codex 工作，并用待办组织需要交给 Codex 的任务。

产品由 Android App 和运行在用户机器上的独立服务组成。App 通过服务复用该机器上 Codex Desktop 的安装、登录、项目、原生会话、运行配置与权限；Codex 不在手机上运行。

App 与 Desktop 使用同一权限上下文。Desktop 能做的 Codex 工作，App 不额外收窄；不设计独立项目白名单、设备权限等级或 App 额外审批。连接只做必要的身份验证，不另建一套产品权限体系。

## 首页与导航

- 没有已登录节点时，首页就是节点登录授权界面。
- 已有登录节点时，首页就是项目列表；点击项目进入该项目的会话列表，再进入具体会话。
- 未登录时按本产品要求提供节点登录授权；已登录后的项目列表布局及后续浏览流程沿用 QiGuang 现有设计。不另设首页口号、大入口或欢迎总览页，也不默认跳进某个项目的会话列表。
- 节点登录授权用于确认连接身份，不代表另设操作权限；登录后仍复用 Desktop 的配置与权限。

## 登录授权

- 以扫描电脑端服务生成的二维码为主，同时提供手动输入入口，支持粘贴完整配对链接，或输入节点地址与配对码。
- 二维码和手动码使用同一短期、一次性配对流程；成功后保存连接凭据，后续自动重连。手机不另行登录 OpenAI，也不接收 Desktop 的登录密钥。
- 电脑端可以撤销手机连接。普通断网保留登录状态并提供重连；凭据失效后回到登录授权界面。
- 首版先完成一台 Mac 服务和一个当前节点的闭环，多节点管理后续再按需求加入。

## 核心功能

### Codex

- 连接服务并浏览 Desktop 中的项目与 Codex 原生会话，沿用同一登录、运行配置和权限。
- 查看原生历史，新建会话，或继续已有会话；显示运行状态、流式输出和执行结果。
- 延续 Desktop 的 Codex 操作能力，包括停止任务，以及按 Desktop 设置产生的原生提问和审批。原生交互原样呈现；Desktop 不要求审批时，App 不另加一道。
- 桌面和手机通过同一个原生 thread 延续上下文。会话写入权（writer）与并发冲突属于底层协调，服务默认自动处理，不要求用户在日常流程中手动获取、释放或接管执行权。
- 涉及中断正在运行任务的动作，执行前清楚说明影响。完整延续是产品验收目标；运行中续接、跨端操作和状态同步的实际能力需要技术验证，不把无中断迁移描述为已经实现。

### 待办

- 新建、查看、编辑、完成和删除待办。
- 将待办交给选定项目中的 Codex 会话执行，并保留待办与会话的关联。
- 待办从全新数据开始，不迁移 QiGuang 待办或其客户端缓存。

首版待办聚焦上述闭环，分类、子任务、提醒、附件和离线同步延后，后续按实际需求补充。

## 数据与状态边界

- Codex 原生 thread、turn 和 item 是会话历史的权威来源。服务通过 Codex 提供的接口读取原生数据，不建立第二份权威聊天历史。
- Android 的展示模型和服务的协议适配可以转换原生数据；发送中或流式内容可以作为临时状态，但不能覆盖或伪造原生历史。
- 新服务拥有自己的待办和必要运行状态，包括连接配置、关联信息及确有需要的临时提交或事件状态。它们从空白开始，不迁移 QiGuang 数据或 sidecar。
- 同一会话的写入权和并发操作由底层自动协调；不得因连接失败或重启而自动重放无法确认是否已经执行的指令。
- 服务沿用 Desktop 的项目访问范围、运行配置和权限，不另外限制 App 能访问的项目和数据。连接通过配对凭据验证身份，密钥不能写入仓库或日志；具体数据边界见[架构设计](architecture.md)。

## 产品范围

首要平台为 Android 客户端和运行在 macOS 上的服务。其他平台留待需求明确后评估。完整延续的范围是 Codex 工作，产品仍只围绕 Codex 和待办，不扩展为整个桌面的远程控制，也不包含 QiGuang 的通用聊天、NAS、家庭设备或其他业务，以及 QiGuang Manager 的发布控制面。

本项目是独立产品，可以参考 QiGuang 的实现，但不要求兼容其私有 API、运行状态或部署体系。采用任何既有代码前应核对依赖和适用的授权。
