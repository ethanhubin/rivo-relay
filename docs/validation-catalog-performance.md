# 项目目录读取优化验证（2026-11-09）

## 依据与只读测量

最近一小时日志窗口为北京时间 19:19:49–20:19:49：主节点 1,221 次完成记录中，项目类请求 24 次全部为 504，会话类 21 次 504。45 次 504 全部能按 request_id 关联到网关 CancelledError；19 次耗时超过 29 秒。原实现把截止时间和客户端断开均归为 read_deadline，不能把全部 504 直接当作服务端故障。

在当前主节点上建立独立只读原生连接，未切换生产服务、未恢复会话或发送任务：

- 项目元数据 21 项，约 1–2 ms。
- 合并原生扫描与状态库的会话列表 610 项，约 9.1–9.6 秒。
- 工作区关联扫描约 2.6–2.8 秒。
- 610 个目标查询约 0.8 秒；最初 10 项抽样约 19 ms。
- 真实 `CodexService.list_projects()` 的原执行状态阶段约 36.9 秒后中断，整体约 48.8 秒，已超过设置的 45 秒协作预算。日志预算只在检查点生效，不代表硬实时中断。
- 原生分页请求即使传 limit=500，实测仍只返回 100 条，因此未采用增大分页的无效优化。

记录位于 `workspace/artifacts/catalog-analysis/`。仅输出阶段、计数、耗时和错误类别，未保存会话内容、名称、项目路径或原始 RPC 响应。

## 改动与结果

项目计数只需要“确实在运行”的证据。新增仅供项目计数使用的 runningOnly 检查：先检查 writer 锁，无锁会话不可能满足原来的“运行中日志且 writer 占用”条件，因此跳过其整份历史解码，不伪造 idle；有锁会话仍完整检查生命周期和日志稳定性。会话列表、详情、历史修复和操作准入继续使用完整状态检查。

优化后的同规模真实读取成功返回 22 项（包含“最近”虚拟项目），总耗时 17.891 秒：目录扫描 9.554 秒、工作区 2.810 秒、运行状态 4.669 秒、目标 0.850 秒。这是单次服务端只读对照，未声称手机端已经提速或证明所有负载下均小于 30 秒。

另外：

- 项目刷新锁改为可响应读取预算/连接取消的等待，取消排队者不会取消持锁刷新者。
- `thread/tokenUsage/updated` 不再使项目缓存失效；项目/会话生命周期与目标事件仍使缓存失效。
- 项目阶段事件通过 request_id 关联 HTTP 请求，记录五个阶段的耗时及条目数。
- HTTP 日志区分 deadline、client_disconnected、connection_closed，保持现有对客户端的 read_deadline 协议；业务错误码仅记录固定白名单，未识别码记 other。
- 网关增加脱敏路由类别与 HTTP 方法，方便定位其他节点的 409，不记录路径、查询参数、异常正文或凭据。

## 第二轮：共享目录与批量探测

- 项目页和会话页按原生查询参数与运行时 generation 共享完整合并目录；TTL 为 10 秒，最多保存 8 个查询。相同查询并发只扫描一次，返回深拷贝。事件失效不等待扫描，扫描期间发生失效则不缓存结果；失败和运行时切换不缓存。无通知的外部元数据变化最多存在 10 秒缓存窗口。
- 创建、置顶、归档成功后同步失效，不依赖通知到达顺序；原生生命周期通知继续失效。归档准入与执行状态判断不使用目录缓存替代实时检查。
- 一次批量执行状态读取共用本地 socket/进程归属证明，返回前重新核验；每批仍校验运行时，每个 writer 锁仍实时读取，不跨读取复用证明。
- 工作区 helper 仅在单次扫描内复用规范路径和相同 Git 查询；归属歧义仍保留。受控夹具 Git 调用 12→4；真实节点此阶段没有明显改善，不能把夹具收益外推。

整合后的独立只读连接测量（610 会话，21 原生项目，返回含虚拟项目共 22 项）：首次 13.913 秒，目录 8.996 秒、工作区 2.747 秒、执行状态 1.325 秒、目标 0.836 秒。紧接着相同目录查询命中为 0.039 秒；在此独立服务实例中仅使项目统计缓存过期，再读项目为 1.699 秒，其中目录 0.033 秒、工作区 0.001 秒、实时执行状态 0.818 秒、目标 0.840 秒。记录为 `service-integrated.log`；单次测量并非延迟分位数，也不代表生产或手机端已经应用。
