# 更新下载性能排查与验证

日期：2026-11-09（北京时间）。问题：手机 APK 下载长期只有约 100 多 KB/s，用户反馈 VPN 开关均可复现。

## 现场证据

- 原 APK 为 0.2.86，大小 19,186,694 字节。VPS CUBIC 慢连接在约 114 秒内确认约 13.8 MB，RTT 约 183 ms，累计重传 867,416 字节/659 段，发送窗口 12 段、MSS 1,320 字节，仍有约 578 KB 未发送。窗口/RTT 估算约 86 KB/s，与当时发送速率量级一致。这说明有数据等待发送，链路拥塞控制在限制吞吐；不能仅凭这些计数确定丢包发生在哪一跳。
- 本机公网、禁用 curl 代理并使用 SSH 获取的 VPS 公共证书校验：首次完整下载 36.756 秒、522,006 B/s；两路各 4 MiB Range 合计 2.440 秒、约 3.44 MB/s；之后一次单连接完整下载 0.529 秒、36,284,009 B/s。后两次不是受控 A/B，不能据此宣称并行或任何修复带来提速；短时结果也不代表稳定带宽。
- VPS 自身通过 HTTPS 读取同一 APK 0.512 秒、约 37.5 MB/s；负载约 0.04。服务器回环测试不能衡量公网或手机速度，也不能用它排除公网限速/竞争。
- 原更新接口未记录下载日志，业务中转日志不能替代 APK 下载记录。ADB 无已连接设备，未取得手机 logcat。

## 本地修复

- 更新文件连接尽可能选择 BBR，失败保留原算法；保留 aiohttp 文件响应及 Range、HEAD、条件请求语义，不修改全机默认算法。
- 增加下载开始/结束事件、响应关联 ID、发送耗时和 Linux TCP 指标；中断不记成功，不把服务端发送完成当作手机收齐或安装成功。

## 已完成验证

- macOS：下载传输 7 项测试及现有离线更新/Range 回归，共 8 项通过。覆盖 BBR 不可用/无权限回退、非 Linux、关闭调优、TCP 指标解析、完整响应/续传/HEAD/304/416、取消/断连与最终 flush 异常。
- VPS Linux：在 `/tmp` 隔离目录执行同一组 7 项传输测试，通过；未替换正在运行的服务代码。
- VPS 内核支持 BBR；测试 socket 从 CUBIC 切换为 BBR，普通 `rivo-gateway` 用户也可选择 BBR。探测按内核机制加载了自带模块，主机默认仍为 CUBIC，未写持久配置。
- VPS 隔离回环 HTTPS 服务使用新响应实现及现有证书：完整 APK 大小和 SHA-256 一致，偏移 12,345 字节的续传内容一致；两次请求日志分别确认 `selected_bbr` / `already_bbr`。总计约 0.563 秒，仅验证 Linux/TLS/完整性/keep-alive 的实现正确性，不作为提速证据。

## 边界

未部署到生产网关，未发布 APK，未做真机或模拟器验证；尚不能确认手机已恢复约 3.4 MB/s。部署后应在同一手机网络分别以默认 BBR 和 `RIVO_UPDATE_CONGESTION=system` 做完整下载对照，记录客户端总耗时及服务端关联事件，再判断效果。未运行无关全量测试或 lint。
